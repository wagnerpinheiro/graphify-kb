# graphify: required install from the fork, scope, build and coexistence

graphify (package `graphifyy`, skill `graphify`) builds an exploratory knowledge graph (communities, god nodes, `query`/`path`/`explain`). For code it extracts structure by AST (deterministic, no LLM). For documents it uses the host agent (subagents) to read whole files — so it falls under per-document authorization.

**graphify is required in every KB workspace.** kb-setup is versioned inside the graphify-kb fork (`https://github.com/wagnerpinheiro/graphify-kb`, folder `kb-setup/`), so skill and graphify move together. Expected version: **0.9.76** (the fork's `pyproject.toml`; the workspace records it in `kb/config.yaml` → `graphify.version`). Never install `graphifyy` from PyPI for a KB workspace: upstream releases are not the version this skill was tested with.

## Install (once per machine; nothing is installed in the workspace)
Never `pip install` into the workspace (no `.venv` in OneDrive folders). Install graphify as a uv tool from the fork:

1. **Preferred — the fork checkout** (the same clone that provides `~/.claude/skills/kb-setup` through a symlink). Find it with `readlink ~/.claude/skills/kb-setup` (its parent folder is the repo), then:
   - `uv tool install --force -e <repo>` (editable: a `git pull` in the fork updates graphify and kb-setup together);
   - `graphify install --platform claude` (writes the global skill `~/.claude/skills/graphify`).
2. **Portable fallback — no clone** (teammates who only need graphify): `uv tool install --force "git+https://github.com/wagnerpinheiro/graphify-kb@v8"` then `graphify install --platform claude`. Replace `@v8` with a commit or tag to pin exactly. For a one-off command without installing, `uvx --from "git+https://github.com/wagnerpinheiro/graphify-kb@v8" graphify --version`.
3. **Why a uv tool and not plain `uvx`:** the graphify skill's Step 1 resolves its interpreter with `uv tool run --from graphifyy`. With the fork installed as the `graphifyy` uv tool, that resolves to the fork; without it, Step 1 installs `graphifyy` from PyPI (wrong version).
4. **Verify:** `graphify --version` must print the expected version, and `<uv tool dir>/graphifyy/uv-receipt.toml` must show the fork as the source (`editable = "<checkout>"` or `git = "https://github.com/wagnerpinheiro/graphify-kb…"`). If the version differs from `graphify.version` in `kb/config.yaml`, warn the user and offer to reinstall or upgrade (see SKILL.md → upgrade); never rebuild a workspace graph with a different version silently.
5. Running any graphify command refreshes outdated copies of its global skill (`~/.claude/skills/graphify`, Codex, OpenCode), keeping a `SKILL.md.bak`. Set `GRAPHIFY_NO_AUTO_REFRESH=1` to disable it.
6. Never run `graphify claude install` (writes a PreToolUse **hook** and a CLAUDE.md section) nor `graphify hook install` — they conflict with managed policies. The coexistence rules below replace them.
7. Record in `kb/SETUP.md`: version, source (`fork checkout <path>` or `git+…@<ref>`), install date and scope.

## Scope (default: code + docs/ + wiki/; raw/ only authorized documents)
- Build from the workspace root so `graphify-out/` lands in the root. graphify also writes a semantic **cache inside the scanned directory** (e.g. `raw/graphify-out/cache/`) — it contains extracted document content: keep `graphify-out/` ignored by git at any level (the kb-setup .gitignore block does) and excluded by the engine (default `never_index`).
- Root `.graphifyignore` (gitignore syntax): exclude `kb/` (generated by the engine) and `.claude/`. graphify also reads nested `.graphifyignore` files, so per-document scope lives in `raw/.graphifyignore` (template `assets/templates/graphifyignore`): list every raw/ file or folder NOT authorized — by default all of raw/'s contents. Prefer explicit lines over `*` plus `!` negations: as in gitignore, a negation cannot re-include a file whose parent folder is excluded. Check the result with the detect step (file names only) before any extraction; abort if anything unauthorized appears.
- graphify respects `.gitignore`: it sees the converted `.md` files but not the binaries (L48).
- Before semantic extraction: `env | grep -c -E '^(GEMINI_API_KEY|GOOGLE_API_KEY)='` must be 0 — with those keys graphify sends content to Google.
- Never use `graphify add <url>` in workspaces where raw/ holds official sources (it writes into ./raw), nor `graphify extract` with an external backend, `--mcp`, `--neo4j`, `--falkordb`, `--watch`, hooks (`graphify hook install`, `graphify claude install`) — they conflict with managed policies or confidentiality.

## Build and update (always in a subagent — they read whole documents)
- **init / adopt:** after the scope files exist, run `graphify update .` from the workspace root: a structural build with no LLM (AST for code, headings/links for Markdown) that always produces `graphify-out/graph.json` and `GRAPH_REPORT.md`. Then, when docs/, wiki/ or authorized raw/ files hold real content, a subagent runs `/graphify .` (host-agent semantic extraction). Deliverable from the subagent: node/edge counts and the list of scanned files (names only). Log the semantic cost with `KB log-cost --kind graphify-build --config graphify`.
- **Empty workspace:** `graphify update .` is enough (the graph starts with the example notes); later updates grow it.
- **update:** `graphify update .` (code only, AST, no LLM) when only code changed; `/graphify . --update` in a subagent when docs/, wiki/ or authorized raw/ files changed. Log with `--kind graphify-update`.
- Widening scope (new raw/ document) requires a new authorization line in `kb/SETUP.md` before removing it from `raw/.graphifyignore`.

## Coexistence rules (write them into the workspace CLAUDE.md)
- Questions about the sources (documents, notes, requirements, deadlines, responsibilities) go to `/kb` even when `graphify-out/` exists — graphify's description claims "any question about the project" and its fast path answers first when the folder exists; without the rule, routing is ambiguous (observed in a test).
- graphify is used when the user asks for it explicitly, for exploration (themes, communities, paths between concepts) or for code.
- Authorized graphify scope = files not listed in `.graphifyignore`; widening requires per-document authorization.

## What the eval showed (one run, 12 questions, 6 documents)
KB: 24/24 accuracy, 24/24 citation; graphify: 21/24 and 18/24; no hallucinations in either. graphify needed fewer calls for aggregation/negative/relation questions; KB won on figure content, cross-document facts and page-level citation, with far lower build cost (graphify semantic extraction ≈ 300k tokens for ~55k words). Conclusion: coexist with separate scopes; no data bridge by default.
